# Licensing — what is under which licence, and why

> **Decided 2026-09-11.** Code under **AGPL-3.0-only**, research notes and
> figures under **CC BY 4.0**, raw measurement records under **CC0 1.0**,
> third-party components under their own licences, and contributions under a
> **Contributor License Agreement** signed before any outside merge. The root
> `LICENSE` is the unmodified AGPL text so GitHub and tooling recognise it;
> this file and `NOTICE` carry the scope.
>
> None of this is legal advice.

## The three parts

The line between the parts is **function, not file extension**. A JSON file
that code loads is configuration; a JSON file that code only writes is data.

| part | licence | what falls in it |
|---|---|---|
| Code, configuration, calibration | AGPL-3.0-only (`LICENSE`) | every `.py`, `.sh`, `.yaml`, `.toml`; `.github/`; test fixtures; data files that code **loads as an input** — today `research/style_feature_stats.json` (the coherence instrument's per-character statistics), `research/corpus_exclusions.json` (the licence filter), the distinctiveness tables the selectors read (`font_distinctiveness`, `pool_distinctiveness`, `holdout_distinctiveness`), `research/candidate_references.json` (the prompt set the CLIP scripts read), `research/expansion_set.json` and `replacement_set.json`, `research/sidebearing_prior.json`, and `research/corpus_provenance.json` (a test fixture) |
| Research notes, documentation, figures | CC BY 4.0 (`LICENSES/CC-BY-4.0.txt`) | `research/*.md`, `docs/*.md`, `README.md`, `CLAUDE.md`, `AGENTS.md`, the package READMEs, `viz/**/*.png` and `.gif` |
| Measurement records | CC0 1.0 (`LICENSES/CC0-1.0.txt`) | the tracked `eval_runs/**/per_cell.json` and `scores.json`, `training_*/metrics.csv` and `train_config.json`, `probe_*/metrics.csv`, `bestofn_*/scores.json`, and every `research/*.json` that no script loads |
| Third-party components | their own | `route_b/` is modified Nunchaku, Apache-2.0 (`route_b/NOTICE`, `route_b/LICENSE.nunchaku`); the base models are downloaded separately (4B Apache-2.0, 9B non-commercial) |

Two edges worth stating:

- **A figure generated by AGPL code is not AGPL.** AGPL covers program
  output only when the output is itself a covered work; a rendered PNG is a
  picture. The plotting script is code; the picture is a figure.
- **CC BY does not cover what the notes quote.** Several notes reproduce
  licence text (the SIL OFL FAQ, for instance), model-card language and
  other authors' material. Those keep their own terms and are excluded from
  the CC BY grant. So are trademarks and logos, of which this repository
  uses none deliberately.

## Why these three

**AGPL-3.0-only for the code.** The project may become a service. AGPL's
section 13 obliges anyone who *modifies* the program and lets users interact
with it over a network to offer those users the source. That does not stop
competition: running the unmodified code as a service is unconditional, and
a modified service may charge as long as its source is offered. What it
stops is a **closed fork** of the instruments and pipeline. Since the product
code itself is held in the private archive (`public-release.md`), a closed
fork is the only exposure the public tree has, and "open forks only" is the
right outcome for a portfolio. BSL 1.1 would restrict production use more
strongly, and was rejected because it is not open source and would label a
research repository as a gated product. Apache-2.0 and MIT were rejected
because they permit exactly the closed service the owner wants to keep for
themselves; MIT was in fact removed on 2026-08-18 for that reason.

"Only", not "or later": the owner, as licensor of a possible dual-licensed
product, should not let future licence versions nobody has read govern the
public code.

**CC BY 4.0 for prose and figures.** A software licence fits a research note
badly, and a reader who wants to quote a finding or reuse a figure should be
able to, with attribution. That is the behaviour a portfolio wants.

**CC0 for raw records.** Attribution on dozens of small JSON measurement
files is a burden nobody would honour; a public-domain dedication is the
honest grant for numbers.

## The owner's position, and why the CLA exists

As copyright holder the owner is not bound by AGPL for their own service and
may license the code commercially. That is true only for code whose copyright
the owner controls. An outside contribution accepted under AGPL alone is
AGPL-only forever, and the FSF is explicit that relicensing then needs that
contributor's permission. So **every outside contribution is accepted under
the Contributor License Agreement in `.github/CLA.md`**, which leaves the
contributor their copyright and grants the owner (and successors) a
perpetual, irrevocable, sublicensable licence to use the contribution under
any terms, plus a patent grant and an authority warranty. A pull request from
anyone other than the owner is reviewed, but **not merged until the
contributor's signature line is in `.github/CLA-signatures.md`**. The PR
template's checkbox is a reminder of that, not a substitute for it.

## What no code licence touches

The README's Licensing section states two constraints that the choice above
does not affect, because neither weights nor outputs are in the repository:

1. **Right to train.** The early corpus contained 49 fonts under vendor terms
   permitting rendering but not conversion, and 36 more under a licence that
   claims derivative works. They are out of the training set; the existing
   checkpoints were trained on them. No output licence cures this.
2. **Generated fonts are OFL derivatives** per SIL OFL FAQ 1.25, which is
   more than "include the OFL file": a distributed font must carry the
   applicable copyright and licence notices of its sources, respect Reserved
   Font Names, and cannot be placed under another licence. Anything sold
   would be sold as a service around a font that stays OFL.
3. **The base model defaults.** Two scripts once defaulted to the
   non-commercial 9B; both now default to the Apache-2.0 4B, so a commercial
   deployment that forgets `--model` does not violate the model terms by
   accident. A 9B-derived adapter stays non-commercial regardless of this
   file.

## Not done, on purpose

- **No per-file SPDX headers.** Three hundred files of churn for a statement
  `NOTICE` already makes. Add them if a downstream packager needs them.
- **No CLA bot.** Signatures are a line in a tracked file, reviewed by the
  code owner, which is the same mechanism the CLA-assistant tools automate.
  Install one when the volume warrants it.
- **No trademark clearance** on the name `digital-rain`, and the copyright
  holder is a handle rather than a legal entity. Both belong to the moment a
  company exists; the CLA runs to the holder's successors and assigns so that
  transfer is clean.
