**Smith #41 | Confidence: HIGH | Date: 2024–2026**

**Smith #41 | Confidence: MEDIUM | Date: 2024–2026**

- **Compute cost:** ~33% slowdown (trades speed for VRAM)

### 4A. Structured Pruning at Scale

**Smith #44 | Sources: arXiv 2603.08065 (2025), 2024 GPT-scale research**

- **Layer dropping:** Up to 40% of layers can be dropped before "functional cliff" where performance "substantially degrades" (2024, GPT-scale 7B–70B) | Confidence: MEDIUM
- **At 80% sparsity (27B → ~5.4B):** Not directly measured. Pattern suggests 5–15% absolute performance loss without aggressive fine-tuning | Confidence: LOW
- **Structured vs. unstructured:** Structured pruning preserves matrix structure for GPU efficiency but has worse zero-shot performance than unstructured magnitude pruning. Structured is required for actual hardware speedup. | Confidence: MEDIUM

### 4B. Knowledge Distillation (27B → 3B)

**Smith #44 | Multiple 2025–2026 sources**

- **3B / 27B capacity ratio:** ~11% (1/9 teacher size) — "extreme compression ratio, well beyond typical industry practices"

- **With curriculum learning (2025 method, arXiv 2506.05695v1):** Could reduce loss by ~1–2% | Confidence: MEDIUM
- **Key risks:** Distributional shift, mode collapse, catastrophic forgetting (2025, ACL/EMNLP papers) | Confidence: MEDIUM

- Quality loss likely manifests as malformed SVG coordinates, broken glyph shapes
- Not just lower BLEU/MMLU — functional correctness of SVG output may degrade unpredictably
- **No research found on distilling multimodal generation models like VecGlypher**
- Standard LLM distillation theory may not transfer cleanly

### 6B. Cascaded & Hierarchical Generation

**Primary source: Smith #46 (cascade-cheap-models)**

#### Cascaded Diffusion Models Foundational Work (JMLR 2023, original 2021)
- [arXiv 2106.15282] | Source: JMLR paper v23/21-0635
- Pipeline of multiple diffusion models at increasing resolutions
- **Key innovation:** Conditioning Augmentation — augments lower-resolution inputs to prevent error compounding across stages
- **Performance:**
  - FID 1.48 @ 64×64 | FID 3.52 @ 128×128 | FID 4.88 @ 256×256 | Confidence: HIGH
  - Classification accuracy: 63.02% top-1, 84.06% top-5 @ 256×256 | Confidence: HIGH
  - Outperformed BigGAN-deep

#### DetailFlow: 1D Coarse-to-Fine Autoregressive Generation (May 2025)
- [arXiv 2505.21473] [GitHub: ByteFlow-AI/DetailFlow]
- Resolution-aware token sequence; early tokens = global structure; later tokens = details
- "Next-detail prediction" paradigm (not next-token)
- **Performance (ImageNet 256×256):**
  - gFID 2.96 with 128 tokens vs. VAR (3.3 FID, 680 tokens) and FlexVAR (3.05 FID, 680 tokens) | Confidence: HIGH
  - ~8× faster with self-correcting parallel inference | Confidence: HIGH
- **Key advantage:** Fewer tokens (128 vs. 680) with better FID

#### Coarse-to-Fine Token Prediction (March 2025)
- [arXiv 2503.16194] [GitHub: GzyAftermath/CTF]
- k-means clustering of similar tokens by codeword
- Two-stage: (1) autoregressive coarse label prediction, (2) simultaneous fine label from coarse
- Exploits codebook redundancy

#### MSD-Font: "Generate Like Experts" (CVPR 2024, June 2024)
- [CVPR 2024 proceedings] [GitHub: fubinfb/MSD-Font]
- Mimics expert manual font design process
- **Three stages (cascade):**
  1. Structure construction: source → target character structure
  2. Font transfer: source → target font style
  3. Refinement: enhance appearance and local details
- Diffusion-based; noise and data distributions separable into sub-spaces

#### HQ-Font: Hierarchical Quantization (December 3, 2025 preprint)
- [Research Square, rs-7876044/v1]
- Hierarchical quantization via VQGAN codebook
- Low-level → high-level feature spaces (unsupervised)
- Cross-attention transfers different-grained styles to discrete codes
- Hierarchical decoder: global semantic + local stroke codes → final image
- Variable number of glyph references, no retraining needed
- Different from VQ-Font (AAAI 2024) — see below

#### VQ-Font: Structure-Aware with Quantization (AAAI 2024, February 2024)
- [AAAI Proceedings] [GitHub: Yaomingshuai/VQ-Font]
- VQGAN codebook pre-training + token refinement
- Structure-level recalibration (Chinese radicals & components)
- Addresses missing details and distorted strokes in few-shot FFG

### 6D. GNN-Based Approaches

#### VectorGraphNET (October 2024)
- [arXiv 2410.01336]
- Two-layer Graph Attention Network (GAT) for vector graphics processing
- Designed for technical drawing segmentation (not directly font, but structurally relevant)
- **Architecture:** 1.3M parameters | Confidence: HIGH
- **Efficiency:** 20–50× smaller than PanCADNet (42M+) and CADTransformer (65M+)

#### Why GNNs Are NOT Standard for Font Generation (Smith #45 analysis)

- Existing solutions (DeepVecFont, VecFusion) model glyphs as **sequences**: paths → commands → control points
- GNN approach would require:
  - Node features: control point positions + type (anchor/handle)
  - Edge features: curve segment type (line/cubic Bézier/quadratic), direction
  - Message passing to predict node positions iteratively
- **Advantage:** Explicit geometric constraints via graph connectivity
- **Trade-off:** More parameters for same glyph; existing seq2seq baselines dominate literature

- Geometric constraints preserving SVG expressivity

**VecFusion (Dec 2023/2024)**
- [arXiv 2312.10540]

- Transformer-based vector diffusion for precise control point prediction
- **DEDUP NOTE:** Also appears in Smith #48 with inference time: ~10 seconds per glyph on A100

**DeepVecFont-v2 (CVPR 2023)**

## ── THEME 7: Font Generation Architectures — Autoencoders & Latent Space ──
*Source: #38 primarily; cross-references with #36, #37*

### 7.1 Chronological Architecture Survey

**Erik Bernhardsson "Deep Fonts" (2016) — Foundational**
- 40D embedding for 50,000 fonts — HIGH [erikbern.com, Jan 2016]
- Input: 102D (40D font vector + 62D one-hot char) → multiple dense layers (leaky ReLU α=0.01) → 4096D output (64×64, sigmoid)
- Loss: L1 (explicitly chosen over L2 to avoid "gray" output)
- Enables font interpolation via vector arithmetic — HIGH
- GPU: Not specified; era suggests 1–2 GB

**Srivatsan et al. "Deep Factorization of Style and Structure" (EMNLP 2019)**
- VAE with disentangled content/style latent factors — HIGH [ACL Anthology]
- Architecture: Conv encoder → char content embedding + font style latent variable
- **Key innovation:** Decoder filters are NOT learned via backprop; outputs of small MLP parameterized by font latent variable — HIGH
- Decoder: 4 asymmetric transpose-conv blocks (upscale → halve channels → instance norm → ReLU → 2× regular conv)
- Enables style transfer arithmetic: "bold Times + normal Helvetica → bold Helvetica" — HIGH

**GlyphGAN (Hayashi et al., 2019, Knowledge-Based Systems)**
- DCGAN variant with Wasserstein discriminator — HIGH [arXiv:1905.12502]
- Input vector: character one-hot + uniform random style vector (unsupervised)
- Decouples character identity from style → infinite style diversity per character — HIGH
- Maintains style consistency across batch — HIGH

**Font-VAE (GitHub: hngskj)**
- Input: 112×112 pixels (font size 25) — HIGH
- Encoder: Conv layers (4×4 kernel, stride 2) → max-pool (2×2) → FC: 256D → 16D latent bottleneck
- Decoder: Mirror with ConvTranspose2d stride 2
- VAE loss with KL divergence
- Modular: encoder, decoder, VAE as 3 separate weight-sharing models
- Learnable features: weight, width, rounding, italics, contrast, serifs — MEDIUM (derived from loss function)

**Wu et al. "Scalable Font Reconstruction with Dual Latent Manifolds" (EMNLP 2021)**
- Two disentangled manifolds: character identity + font style (separately) — HIGH [ACL Anthology]
- Two inference networks: one for character latent (across glyphs sharing a char), one for font latent (across glyphs sharing a font)
- Novel adaptive distribution loss in projected space; avoids discriminator — HIGH
- Generalizes to characters never seen during training — HIGH

**DeepSVG (Carlier et al., NeurIPS 2020)** [also in #37]
- Input: SVG format (vector, not raster) — HIGH
- Hierarchical Transformer: disentangles high-level shapes from low-level drawing commands
- Non-autoregressive generation (all shapes predicted in parallel) — HIGH
- Latent space interpolation; font notebook: `fonts.ipynb` available
- GPU: Not specified; estimated 4–8 GB (hierarchical Transformer)
- **⚠️ AGE FLAG:** 2020 (4+ years old) — flagged by both #37 and #38

**FontDiffuser (AAAI 2024)** [also in #33, #36]
- Diffusion-based, one-shot font generation — HIGH [arXiv:2312.12142]
- Multi-scale Content Aggregation (MCA) block: combines global + local content cues across scales
- Style Contrastive Refinement (SCR) module: disentangles styles via contrastive supervision
- ⚠️ TRUNCATION: SCR description cut mid-sentence in #38
- **AGREE (#33, #36, #38):** Consistent across three Smiths on architecture and ~6 sec/char inference on 3090.
- Pretrained weights: available via Google Drive / BaiduYun — HIGH (#33)

### 9.1 Classical Morphable Models

- 53,490 vertices × 160,470 triangles — HIGH

- BFM-2017 update: improved age distribution + facial expression model — HIGH

**Skeleton-based (Topological Skeleton)**
- Medial axis extraction preserves homotopy type via reversible thinning; iteratively removes simple points without altering connectivity — HIGH
- SkeleText (MIT Media Lab): browser tool for skeletonization of typefaces — HIGH

**Medical Mesh Deformation (transferable technique)**
- Template covered with triangular mesh; deformation via spring analogy method — HIGH
- Topology guarantee: "no tearing, no folding, no appearance/disappearance of structures" via connection-preserving constraints — HIGH [Hindawi CMMM 2013]

**DG-Font (Xie et al., CVPR 2021)**

**Deep Deformable Artistic Font Style Transfer (Electronics 2023, MDPI)**

## IV-A. CF-Font: Content Fusion for Few-Shot Font Generation (CVPR 2023) ✦ UNIQUE — Smith #22

**Confidence: HIGH** (CVPR 2023; outperforms prior methods "by large margin" per abstract)
**arXiv**: 2303.14017
**GitHub**: github.com/wangchi95/CF-Font

**Core mechanism:**
- **Dataset**: 300 fonts, 6,500 characters each
- **Basis font selection**: K-Medoids clustering of all training fonts via L1 distance on content feature vectors; selects fonts nearest to cluster centers as "basis fonts"
- **Content blending**: L1-norm weighted sum of basis font content features; weight = similarity distance between target font and each basis font
- Linear interpolation in content feature space before decoding
- Result: Replaces target's content feature with weighted blend of basis features

## IV-V. Bezier Path Blending & Morphing Techniques ✦ UNIQUE — Smith #22

**Confidence: MEDIUM** (from KUTE.js docs and established technique descriptions)

- **Bezier path blending**: Established technique for vector glyphs; interpolate control points and on-curve points between source/target paths
- **Correspondence problem**: Requires point matching between glyphs; point counts must match or be resampled
- **SVG morphing**: Libraries like KUTE.js use polygon geometric operations; cubic morphing more efficient than standard SVG due to fewer interpolation points
- **Font manifold / embedding space**: Project fonts into lower-dimensional continuous vector space where distance ≈ style similarity; linear interpolation in embedding space yields intermediate font styles
- **Triplet loss training**: Some methods learn font-style embeddings directly via style-guided discriminator approach

## VIII-A. DiffVG Core System ✦ UNIQUE — Smith #27 (primary); referenced in #22, #30 implicitly

**Confidence: HIGH** (ACM SIGGRAPH Asia 2020; GitHub last updated 2025-05-17)
**GitHub**: github.com/BachiLi/diffvg
**DOI**: dl.acm.org/doi/10.1145/3414685.3417871
**Authors**: Li et al., 2020

**Core mechanism:**
- Differentiable rasterizer for 2D vector graphics
- Makes rasterization mathematically differentiable via pixel prefiltering
- Enables gradient backpropagation from raster images to vector curve parameters

**Two prefiltering modes:**
- **Analytical prefiltering**: Faster but prone to artifacts (aliasing conflation)
- **MSAA (Multisampling Anti-Aliasing)**: Efficient, high-quality, unbiased gradients w.r.t. curve parameters — recommended for training

**Full pipeline:**
SVG control points → DiffVG rasterizer → image → loss function (pixel-level, perceptual, CLIP) → backprop → control point gradients

**Performance note**: DiffVG backward pass is **slow** due to per-pixel BVH tree lookups and equation solving for curve-pixel containment. Now superseded by faster alternatives (see VIII-D).
